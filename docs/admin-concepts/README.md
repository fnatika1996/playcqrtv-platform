# CQRTV Admin — варианты направления и аудит иконок

Это **концептуальная площадка для выбора владельцем**, а не утверждённый дизайн и не рабочая админка. Она не вызывает API, не меняет данные и не заменяет страницы CQRTV. Смена направления/экрана доступна в контролах наверху; можно открыть прямую ссылку с `direction=a|b|c`, `view=dashboard|users|site|login` и `viewport=desktop|mobile`. На узком экране селектор «Телефон · 390» показывает отдельный мобильный вариант.

Все счётчики и статусы сервисов показаны как `—` / «нет данных». Аккаунты на экране пользователей — только явно обозначенные примеры с доменом `example.invalid`; действия отключены. В форме администратора поля и кнопка — неподключённый макет.

## Три действительно разных направления

| Код | Направление | Структура и характер | Что проверить владельцу |
|---|---|---|---|
| A | **Premium Esports / Command Center** | Постоянная боковая навигация, просторная сводка, тёплый локальный свет на широком command-banner, крупная типографическая иерархия. На телефоне навигация превращается в нижнюю полосу. | Достаточно ли это похоже на премиальный центр управления и не слишком ли велик акцентный баннер. |
| B | **Modern Operations Studio** | Более плотная, спокойная рабочая среда; компактный top-bar, плоская нейтральная поверхность, упор на таблицу и операционные инструменты. Заголовки строже, меньше декоративного свечения. | Удобно ли быстрее работать с аккаунтами и контролами сайта за счёт плотной компоновки. |
| C | **Futuristic Tactical Interface** | Тактическая сетка, угловатые панели, моноширинные микро-метки и тонкие контуры; высокая контрастность и визуальный ритм, напоминающий esports operations HUD. | Не мешают ли сетка/рамки чтению и не выглядит ли интерфейс чрезмерно игровым. |

У всех трёх общий утверждённый брендовый фундамент: тёмные `#101113`, `#17191D`, `#1C1E23`, оранжевый `#FF7629`, Lexend Deca / Teko. Это сравнимые композиционные концепции, но не финальный редизайн. Сначала требуется выбор A/B/C и замечания владельца.

Для каждого направления доступны **Dashboard, Пользователи, Управление сайтом и Вход администратора** в desktop/mobile варианте. При ограниченной ширине таблица остаётся прокручиваемой; навигация становится нижней. В мобильном режиме входная карточка остаётся в одну колонку и не теряет подписи полей.

## Исходный архив и причина монохромного/чёрного вида

Проверен `Icon Play CQRTV.rar`: **1 215 SVG**. Парсер явных `fill`, `stroke`, `stop-color`, `color` обнаружил **1 210 SVG с двумя или более цветами**, 5 с одним явным цветом. Для основной двухцветной группы обычно записана пара `#000000` и `#737374`. Архив не является монохромным по источникам: чёрный основной слой и серый вторичный слой заданы непосредственно в SVG.

Причина на web-страницах различается:

- В публичном `index.html` часть pack-SVG подгружается, проходит через `DOMParser`, встраивается как inline SVG, а чёрный слой превращается в `currentColor`. Цвета одних только внешних дочерних файлов CSS не меняет; существующий обработчик не везде сохраняет вторичный оттенок как отдельную роль. Значительная часть role-picker иконок — вручную написанные однокрасочные inline SVG.
- `admin.html`, `admin-login.html` и `site-control-admin.html` используют `/assets/icons/cqrtv/ui/*.svg` через `<img>`. CSS `color` родителя не наследуется содержимым внешнего SVG. В `admin-login.html` ещё задан `filter:brightness(.12)` для картинки иконки внутри кнопки, что затемняет её на оранжевой кнопке. Файлы при этом остаются двухцветными.
- Поэтому безопасная дорога к управляемому дуотону — контролируемая сборка по manifest: проверять допустимые SVG из архива, нормализовать **только** известные исходные цветовые значения в `var(--icon-primary)` и `var(--icon-secondary)`, и вставлять подготовленный SVG через существующую проверяемую inline-SVG схему. Вариант хранения/вывода в sprite нужно отдельно проверить на CSS-variable inheritance, MIME/CSP и screen-reader semantics. `<img>` и CSS-фильтр не дают надёжного раздельного управления слоями. Скрипты, `foreignObject`, внешние URL и обработчики событий не должны становиться доверенными из-за того, что файл пришёл из архива.

Preview сравнивает исходный SVG как внешний `<img>` и ту же геометрию как inline SVG с двумя CSS-токенами. Контрол «светлый фон» предназначен для проверки контраста. Ни production icon-файлы, ни manifest на этом этапе не меняются.

## Предложенная цветовая система и доступность

SVG берёт `--icon-primary` и `--icon-secondary` на каждом контейнере. Ниже зафиксирован начальный вариант палитры для **проверки перед внедрением**, а не новая утверждённая дизайн-система:

| Состояние | На тёмной поверхности (`#17191D`) | На светлой поверхности (`#F3F3F2`) |
|---|---|---|
| Обычное | `#FF7629` / `#F3F3F2` | `#AD4C12` / `#383A3F` |
| Активное | `#FF9A58` / `#FFF1E7` | `#A7440C` / `#383A3F` |
| Hover | `#FFB57D` / `#FFF7F0` | `#8F3908` / `#292C31` |
| Disabled | `#747980` / `#6C7279` | `#62666C` / `#888B90` |
| Success | `#36A96F` / `#9CE4BE` | `#237549` / `#345743` |
| Warning | `#FFC45E` / `#FFE1A0` | `#805600` / `#533900` |
| Error | `#FF6C73` / `#FFC3C7` | `#B42332` / `#5B2228` |

Значения на светлом фоне намеренно темнее брендового оранжевого, так как светлый `#FF7629` на `#F3F3F2` не даёт достаточный контраст для значимого небольшого пиктографического слоя. Требуются автоматический расчёт контраста по применяемым поверхностям, проверка rasterized SVG в настоящем браузере, zoom 100% и ручной QA всех ключевых иконок/состояний. Иконка-декор имеет `aria-hidden=true`; если она сообщает состояние, рядом остаётся текст и цвет не единственный сигнал.

Для указанной палитры проверено относительное отношение контраста по WCAG (каждый слой относительно фона своей поверхности): минимальное значение среди слоёв **4.01:1 на тёмной поверхности** и **3.08:1 на светлой** (вторичный disabled-слой); все значения >= 3:1. Это проверка выбранных HEX на образце `#17191D` / `#F3F3F2`, а не подтверждение контраста каждой иконки на любых реальных карточках. Нужна финальная проверка на конкретных утверждённых подложках и на обычных/hover/focus/disabled состояниях.

## Область этого PR и ограничения

- Только концепт под `docs/admin-concepts/`, источники SVG-примеров и автономная проверка превью.
- Нет изменений в `admin.html`, `admin-login.html`, `site-control-admin.html`, публичных страницах, API, PostgreSQL, auth/session, игровых сценариях, icon manifest или production assets.
- Нет слияния, production deploy, обновления VPS/DB, изменения режима сайта, выдачи админ-доступа или начальной настройки admin user.
- Внешний Google Fonts URL в preview — косметический fallback к системному шрифту; локальные иконки не запрашивают сеть. Макеты не подключают production backend.
- На этом этапе ждём, какой вариант (A/B/C) выбрать, и подтверждение Logout-кандидата. Только затем можно готовить отдельную реализацию выбранного макета/семантических иконок.
